# Upgrading

Notes for upgrading an existing installation. The [changelog](../changelog.md) lists every change; this page lists
what you may have to do.

## From 0.2 to the release with *Operations & deployment* (M9)

### Breaking changes

- **The LLM SDKs are optional extras.** `pip install arcviz-agent` alone no longer starts the server. Install the
  SDK of your provider: `pip install "arcviz-agent[anthropic]"` or `pip install "arcviz-agent[openai]"`. For Entra ID
  with Azure OpenAI use `[azure-openai]`, for Cosmos DB `[cosmos]`, for telemetry `[telemetry]`. Without the SDK, the
  start stops with a message naming the extra. **The Docker image is unaffected**: it installs every extra.
- **Configuration is checked at start-up.** A malformed value stops the start with one message listing every
  problem (variable, expected format, value), where it used to start and fail later or behave oddly:
  - an unknown `ARCVIZ_PROVIDER`, and a malformed `ARCVIZ_LLM_TIMEOUT` or `ARCVIZ_LLM_MAX_RETRIES` (these used to
    answer HTTP 503 on the first chat);
  - `ARCVIZ_MAX_ROUNDS` or `ARCVIZ_CHAT_KEEP` below 1, negative agent settings, and `ARCVIZ_PORT` outside 1–65535.

  `arcviz` exits with status 2. Fix the listed variables and start again.
- **No documentation on GitHub Pages any more.** Every installation serves the documentation of its own version
  under `/docs` (menu **Hilfe**); the sources are under `docs/` in the repository. The old Pages site is no longer
  updated.
- **For contributors:** `requirements-docs.txt` is gone; `make install` installs the docs toolchain from `uv.lock`.
  Building a wheel or sdist needs the documentation site first (`make docs-bundle`).

### Changed behaviour worth knowing

- `X-Request-ID` on responses is now always generated by the server. A request id your ingress or client sends is
  logged as `client_request_id`.
- In the default `text` log format, the app's own INFO lines (one per chat turn, migration notes) now appear next to
  uvicorn's.

### New, optional

- JSON logs for a log collector: `ARCVIZ_LOG_FORMAT=json`, with `ARCVIZ_LOG_PSEUDONYM_KEY` (a secret) for the
  pseudonymous `user` field. See [Configuration: logs and telemetry](../reference/configuration.md#logs-and-telemetry).
- Traces and logs to Application Insights or an OpenTelemetry collector: `ARCVIZ_TELEMETRY`.
- Keyless Azure OpenAI with the app's managed identity: `ARCVIZ_OPENAI_AUTH=entra` (see
  [Deploy to Azure](../deploy-azure.md#keyless-azure-openai-entra-id)).
